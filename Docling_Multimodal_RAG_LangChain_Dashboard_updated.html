Docling + LangChain Overview

What Docling does

Docling is an open-source document-understanding framework from IBM. It converts PDFs, Word documents, presentations, HTML, images, and scanned pages into a structured representation that preserves headings, paragraphs, lists, tables, layout, and reading order.

PDFDOCXPPTXHTMLImagesScanned documents

Why pair it with LangChain?

Docling performs document understanding. DoclingLoader exposes the result as standard LangChain Document objects with page_content and metadata, ready for splitting, embedding, indexing, and question answering.

Core idea
Better document structure produces cleaner chunks and more useful metadata.
Source document→Docling conversion→DoclingDocument→DoclingLoader / chunker→LangChain Documents

Why traditional extraction can fail

Broken tables
Lost headings
Wrong reading order
No layout awareness
Weak chunk boundaries
Limited provenance
CONCEPT

DoclingDocument vs LangChain Document

Core Docling

DocumentConverter returns a conversion result whose .document is a DoclingDocument.

  • Rich hierarchy and layout
  • Tables, pictures, lists, sections
  • Reading order and provenance
  • Export to Markdown or dictionary

Docling through LangChain

DoclingLoader.load() returns list[Document], where each item is a LangChain Document.

  • page_content contains text/Markdown
  • metadata carries source/provenance
  • Works with LangChain downstream components
Interview-ready answer: Core Docling creates a DoclingDocument. LangChain's DoclingLoader converts Docling output into standard LangChain Document objects. The final type is familiar, but its content is richer because Docling first understands document structure.
from docling.document_converter import DocumentConverter

conversion = DocumentConverter().convert("report.pdf")
docling_doc = conversion.document
print(type(docling_doc))
print(docling_doc.export_to_markdown()[:1000])

from langchain_docling import DoclingLoader
from langchain_docling.loader import ExportType

docs = DoclingLoader(
    file_path="report.pdf",
    export_type=ExportType.DOC_CHUNKS,
).load()

print(type(docs[0]))
print(docs[0].page_content[:500])
print(docs[0].metadata)
SCOPE

Is Docling a Universal Loader?

Best description: Docling is a universal document loader, not a universal data loader.

Good fit

  • PDF, including complex layouts
  • DOCX and PPTX
  • HTML, Markdown, and text documents
  • Images and scanned documents via OCR
  • Reports, policies, manuals, and research papers

Use specialized tooling instead

  • CSV / Parquet: pandas or dedicated loaders
  • SQL: database connectors
  • REST APIs: API-specific ingestion
  • Audio/video: speech and media pipelines
  • Streaming/time series: source-native connectors

CORE API

DoclingLoader: MARKDOWN vs DOC_CHUNKS

ExportType.MARKDOWN

Returns one LangChain Document for the converted input. Best for inspecting the complete structured Markdown or applying your own heading-aware splitting.

ExportType.DOC_CHUNKS

Returns multiple document-aware chunks. HybridChunker is the default chunker for DOC_CHUNKS, so you do not need to specify it in every DoclingLoader call. This is the preferred starting point for most LangChain RAG ingestion flows.

Default behavior to remember: ExportType.DOC_CHUNKS uses HybridChunker() by default. You can omit chunker=HybridChunker() from the loader examples. Specify a chunker explicitly only when customizing chunking, such as tokenizer alignment.
from langchain_docling import DoclingLoader
from langchain_docling.loader import ExportType

markdown_docs = DoclingLoader(
    file_path="data/complex_report.pdf",
    export_type=ExportType.MARKDOWN,
).load()

chunk_docs = DoclingLoader(
    file_path="data/complex_report.pdf",
    export_type=ExportType.DOC_CHUNKS,
).load()

for i, chunk in enumerate(chunk_docs[:5], 1):
    print(f"--- CHUNK {i} ---")
    print(chunk.page_content)
    print(chunk.metadata)
Version note: Inspect the metadata keys produced by your installed version. Do not assume every release exposes identical page or provenance fields.
PRACTICE

Loading Different Document Formats

The same loader entry point works across supported document formats. Validate output quality for each format, especially tables, images, and scanned pages.

from pathlib import Path
from langchain_docling import DoclingLoader
from langchain_docling.loader import ExportType

supported = {".pdf", ".docx", ".pptx", ".html", ".htm", ".md", ".txt"}
all_docs = []

for path in Path("documents").rglob("*"):
    if path.is_file() and path.suffix.lower() in supported:
        all_docs.extend(
            DoclingLoader(
                file_path=str(path),
                export_type=ExportType.DOC_CHUNKS,
            ).load()
        )

print(f"Created {len(all_docs)} LangChain documents")
PDF ELEMENTS

Text, Headings, and Section Context

Docling exports recognized headings with Markdown markers. LangChain's MarkdownHeaderTextSplitter can then add heading values to section metadata.

from langchain_docling import DoclingLoader
from langchain_docling.loader import ExportType
from langchain_text_splitters import MarkdownHeaderTextSplitter

markdown_doc = DoclingLoader(
    file_path="data/report.pdf",
    export_type=ExportType.MARKDOWN,
).load()[0]

splitter = MarkdownHeaderTextSplitter(
    headers_to_split_on=[
        ("#", "heading_1"),
        ("##", "heading_2"),
        ("###", "heading_3"),
    ],
    strip_headers=False,
)
section_docs = splitter.split_text(markdown_doc.page_content)

for section in section_docs[:5]:
    print(section.metadata)
    print(section.page_content[:500])
Verify: paragraph fidelity, symbols, bullets, footnotes, heading levels, and whether headings are true structural headings rather than ordinary bold text.
PDF ELEMENTS

Tables: Markdown and DataFrames

Path A: Markdown table

Use the loader's Markdown output when the table can be embedded and retrieved as readable text.

Path B: Structured table

Use each Docling table item, export it to a DataFrame/CSV, and wrap the rendered table in a LangChain Document.

from pathlib import Path
from docling.document_converter import DocumentConverter
from langchain_core.documents import Document

conversion = DocumentConverter().convert("data/report.pdf")
docling_doc = conversion.document
Path("output/tables").mkdir(parents=True, exist_ok=True)

table_documents = []
for index, table in enumerate(docling_doc.tables, start=1):
    df = table.export_to_dataframe(doc=docling_doc)
    df.to_csv(f"output/tables/table_{index}.csv", index=False)

    table_documents.append(Document(
        page_content=f"Table {index}
{df.to_markdown(index=False)}",
        metadata={
            "source": "data/report.pdf",
            "element_type": "table",
            "table_number": index,
        },
    ))
Verify: merged cells, multi-page tables, headers, units, footnotes, row alignment, and source-page provenance. Financial and compliance values must be checked against the source.
PDF ELEMENTS

Images, Diagrams, and Charts

Important: DoclingLoader produces text documents. Detecting or exporting a picture does not automatically make its visual meaning searchable. Export the asset, generate a factual description with a vision-language model or human review, then wrap the verified description in a LangChain Document.
from pathlib import Path
from docling.document_converter import DocumentConverter
from docling_core.types.doc import PictureItem
from langchain_core.documents import Document

conversion = DocumentConverter().convert("data/report.pdf")
docling_doc = conversion.document
image_dir = Path("output/images")
image_dir.mkdir(parents=True, exist_ok=True)

image_docs = []
for index, (item, level) in enumerate(docling_doc.iterate_items(), start=1):
    if not isinstance(item, PictureItem):
        continue
    image = item.get_image(docling_doc)
    if image is None:
        continue

    image_path = image_dir / f"picture_{index}.png"
    image.save(image_path, format="PNG")

    # Replace with a caption produced by a VLM and verified against the image.
    verified_caption = "Verified factual description of this image or chart."
    image_docs.append(Document(
        page_content=f"Figure description: {verified_caption}",
        metadata={
            "source": "data/report.pdf",
            "element_type": "image",
            "image_path": str(image_path),
        },
    ))
For charts: validate values, axes, units, series names, legend labels, reporting period, and trend. Never invent a chart description.
PDF ELEMENTS

Scanned Pages and OCR

A scanned page is an image. OCR must recognize its text before LangChain can embed or retrieve it as text. This example configures Tesseract full-page OCR and passes the converter to DoclingLoader.

from docling.datamodel.base_models import InputFormat
from docling.datamodel.pipeline_options import (
    OcrMode,
    PdfPipelineOptions,
    TableStructureOptions,
    TesseractCliOcrOptions,
)
from docling.document_converter import DocumentConverter, PdfFormatOption
from langchain_docling import DoclingLoader
from langchain_docling.loader import ExportType

options = PdfPipelineOptions()
options.do_ocr = True
options.do_table_structure = True
options.table_structure_options = TableStructureOptions(do_cell_matching=True)
options.ocr_options = TesseractCliOcrOptions(mode=OcrMode.FULL_PAGE)

converter = DocumentConverter(format_options={
    InputFormat.PDF: PdfFormatOption(pipeline_options=options)
})

ocr_docs = DoclingLoader(
    file_path="data/scanned_report.pdf",
    converter=converter,
    export_type=ExportType.DOC_CHUNKS,
).load()
Verify: names, dates, decimal points, currency symbols, low-resolution text, table cells, and page references. OCR output is not guaranteed to be perfect.
PDF ELEMENTS

Multi-column Documents

Docling performs layout analysis and reconstructs reading order during conversion. There is no separate multi-column loader switch in this workflow.

from langchain_docling import DoclingLoader
from langchain_docling.loader import ExportType

column_doc = DoclingLoader(
    file_path="data/two_column_paper.pdf",
    export_type=ExportType.MARKDOWN,
).load()[0]

with open("output/reading_order.md", "w", encoding="utf-8") as file:
    file.write(column_doc.page_content)

print(column_doc.page_content[:5000])
Verify: left/right column order, figures, sidebars, equations, and footnotes. Chunking cannot repair an incorrect reading order produced during conversion.

DOWNSTREAM

Optional: Index in Qdrant

Once Docling content is represented as LangChain Documents, it can be embedded and stored in Qdrant. This section stays intentionally limited to the direct Docling-to-LangChain ingestion path.

pip install -U langchain-huggingface langchain-qdrant qdrant-client sentence-transformers
from langchain_huggingface import HuggingFaceEmbeddings
from langchain_qdrant import QdrantVectorStore

embeddings = HuggingFaceEmbeddings(
    model_name="sentence-transformers/all-MiniLM-L6-v2"
)

vectorstore = QdrantVectorStore.from_documents(
    documents=all_langchain_documents,
    embedding=embeddings,
    url="http://localhost:6333",
    collection_name="docling_documents",
)

results = vectorstore.similarity_search(
    "What is the quarterly revenue?",
    k=5,
)
for result in results:
    print(result.page_content)
    print(result.metadata)
