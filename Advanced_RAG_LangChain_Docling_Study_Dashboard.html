Chapter 01 · Beginner

RAG foundations & document ingestion

Understand why the quality of document ingestion affects every downstream RAG stage.

What is RAG?

Retrieval-Augmented Generation combines a retrieval step with an LLM response. Instead of asking the model to answer only from its internal knowledge, the application retrieves relevant source passages and provides them as context.

Why do we need it?

Enterprise knowledge is stored in changing documents, policies, manuals, reports and technical material. Retrieval gives the model access to relevant organization-specific evidence at question time.

What problem does ingestion solve?

Before content can be retrieved, the system must extract it, organize it into useful units, represent those units as vectors and store them with traceable metadata.

Story: enterprise policy assistant

Scenario

An employee asks: “What is the travel reimbursement limit for international trips?” The answer is in a 90-page policy PDF with headings, tables and footnotes.

Without good ingestion: the table may become disconnected values, and the answer may miss the currency or policy section.

With structured ingestion: the loader preserves readable content and structure; chunks retain context; retrieval can find the relevant policy evidence.

Real-world fit

Enterprise search, HR policy assistants, customer support knowledge bases, compliance and technical documentation.

Traditional extraction vs. structure-aware ingestion

The source guide compares `PyPDFLoader` and `DoclingLoader`. The practical difference is not simply the final object type: both can produce LangChain Documents; the content extraction process differs.

Why can a poor PDF extraction result in a poor RAG answer?
Because retrieval can only find and rank the content that was extracted and indexed. If table relationships, headings or reading order were lost during ingestion, later retrieval may not reconstruct them.
Chapter 02 · Beginner to intermediate

LangChain DoclingLoader

Use the LangChain integration as the entry point for loading supported document formats.

What is DoclingLoader?

`DoclingLoader` is the LangChain integration used in your cookbook. It converts a source document through Docling's document-understanding pipeline and exposes the result as LangChain `Document` objects with `page_content` and `metadata`.

Scope choice: examples here use `DoclingLoader`. Standalone `DocumentConverter` / Docling Core code is intentionally not included.

Why use it?

It connects document-aware extraction to a familiar LangChain workflow, so the returned documents can be passed into splitting, embedding, vector storage and retrieval components.

Export type: MARKDOWN

Returns the converted input as a Markdown representation. The cookbook describes one LangChain Document for the converted input document. Use it to inspect the whole structure or apply heading-based splitting.

Inspect / transform

Export type: DOC_CHUNKS

Returns multiple LangChain Documents using document-aware chunking. Your guide identifies `HybridChunker` as the default chunking approach.

RAG starting point
Python · MARKDOWN loader 
from langchain_docling import DoclingLoader
from langchain_docling.loader import ExportType

PDF_PATH = "data/annual_report.pdf"

loader = DoclingLoader(
    file_path=PDF_PATH,
    export_type=ExportType.MARKDOWN,
)

docs = loader.load()

print("Documents:", len(docs))
print("Type:", type(docs[0]))
print(docs[0].page_content[:2000])
print("Metadata:", docs[0].metadata)
Documents: 1 Type: <class 'langchain_core.documents.base.Document'> # Annual Report ## Financial Results ... Metadata: {'source': 'data/annual_report.pdf', ...}

Illustrative shape only. Exact content and metadata keys depend on the input document and installed package version.

  • `DoclingLoader` imports the LangChain integration.
  • `ExportType.MARKDOWN` selects Markdown export.
  • `load()` executes conversion and returns a list of LangChain Documents.
  • `page_content` contains extracted Markdown/text; `metadata` carries source/provenance details.

DOC_CHUNKS example

Python · document-aware chunks 
from langchain_docling import DoclingLoader
from langchain_docling.loader import ExportType

loader = DoclingLoader(
    file_path="data/annual_report.pdf",
    export_type=ExportType.DOC_CHUNKS,
)

chunks = loader.load()

for index, chunk in enumerate(chunks[:5], start=1):
    print(f"--- CHUNK {index} ---")
    print(chunk.page_content)
    print("Metadata:", chunk.metadata)

Expected output: multiple LangChain Documents. Each item has text in `page_content` and provenance/context in `metadata`. Inspect actual metadata keys rather than assuming a fixed schema.

Chapter 03 · Practical cookbook

PDF elements: LangChain-first cookbook

Each element needs a different validation strategy. Use the LangChain loader wherever the uploaded cookbook supports it.

Important boundary: the source cookbook uses Docling Core APIs for low-level table objects, picture export and OCR converter configuration. Those code paths are omitted here as requested. The examples below show the LangChain side and clearly mark where a separate visual/OCR stage is needed.
1. Normal PDF text

What happens: `DoclingLoader` converts document text into Markdown or chunks. Validate paragraphs, symbols, hyphenated words, bullets, footnotes and page breaks.

Python · LangChain loader 
from langchain_docling import DoclingLoader
from langchain_docling.loader import ExportType

docs = DoclingLoader(
    file_path="data/report.pdf",
    export_type=ExportType.MARKDOWN,
).load()

full_text = docs[0].page_content
print(full_text[:2000])

Expected: a Markdown/text representation in the first LangChain Document. For RAG, use `DOC_CHUNKS` or split at meaningful headings rather than embedding a large report as one vector.

2. Headings and hierarchy

What happens: recognized headings appear as Markdown heading markers. LangChain's `MarkdownHeaderTextSplitter` can preserve heading values in section metadata.

Python · heading-aware split 
from langchain_docling import DoclingLoader
from langchain_docling.loader import ExportType
from langchain_text_splitters import MarkdownHeaderTextSplitter

markdown_doc = DoclingLoader(
    file_path="data/report.pdf",
    export_type=ExportType.MARKDOWN,
).load()[0]

headers = [
    ("#", "heading_1"),
    ("##", "heading_2"),
    ("###", "heading_3"),
]

splitter = MarkdownHeaderTextSplitter(
    headers_to_split_on=headers,
    strip_headers=False,
)
sections = splitter.split_text(markdown_doc.page_content)

for section in sections[:5]:
    print(section.metadata)
    print(section.page_content[:300])

Validate: heading level and section context. A bold sentence in the PDF is not automatically a section heading.

3. Tables

LangChain route: Markdown export may represent recognized tables using Markdown table syntax. That content can be indexed as part of the LangChain Document.

Python · inspect Markdown tables 
from langchain_docling import DoclingLoader
from langchain_docling.loader import ExportType

doc = DoclingLoader(
    file_path="data/annual_report.pdf",
    export_type=ExportType.MARKDOWN,
).load()[0]

for line in doc.page_content.splitlines():
    if "|" in line:
        print(line)

Why keep headers? The value `10000` is ambiguous without the column label, unit and row label. Preserve headers and row relationships.

The cookbook's DataFrame/CSV extraction uses Docling Core `TableItem` access. No LangChain-only table-object extraction API is shown in your source files, so this portal does not invent one.
4. Images and diagrams

What is searchable? The loader's text output does not guarantee that the meaning of every picture is searchable. The cookbook exports picture assets, then uses a vision-language model (VLM) or human review to create a verified caption.

LangChain representation after captioning:

Python · store a verified caption 
from langchain_core.documents import Document

verified_caption = (
    "Architecture diagram showing the ingestion service, "
    "queue, processing workers and vector database."
)

image_doc = Document(
    page_content=f"Figure description: {verified_caption}",
    metadata={
        "source": "data/report.pdf",
        "element_type": "image",
        "image_path": "output/images/picture_12.png",
    },
)

Expected: a LangChain Document whose text caption can be embedded and searched. The image path points to the original asset. Replace the illustrative caption with a verified description.

Picture export itself is a Docling Core operation in the uploaded cookbook. This code only shows the LangChain document created after the image has been exported and described.
5. Scanned pages and OCR

A scanned page is an image, so OCR must recognize its text before it can be embedded as text. The source cookbook configures OCR through Docling's PDF pipeline and passes the configured converter to `DoclingLoader`.

LangChain output inspection:

Python · consume OCR-enabled loader output 
# `ocr_loader` is a DoclingLoader configured with
# an OCR-enabled converter in the document pipeline.
# The converter setup is intentionally omitted here
# because it uses Docling Core pipeline APIs.

ocr_docs = ocr_loader.load()

for doc in ocr_docs[:5]:
    print(doc.page_content)
    print(doc.metadata)

Validate: names, dates, decimal points, currency, table cells and low-resolution text. OCR is not guaranteed to be perfect.

The uploaded source's Tesseract configuration is Docling Core configuration, not a LangChain-only API. Use the source's official OCR reference for that configuration; do not assume the normal loader automatically OCRs every scan.
6. Multi-column PDFs

Two-column research papers are difficult because naïve extraction can mix left and right columns. Docling performs layout analysis and reading-order reconstruction during conversion; LangChain receives the converted result.

Python · LangChain DoclingLoader 
from langchain_docling import DoclingLoader
from langchain_docling.loader import ExportType

doc = DoclingLoader(
    file_path="data/two_column_research_paper.pdf",
    export_type=ExportType.MARKDOWN,
).load()[0]

print(doc.page_content[:5000])

Validate: inspect pages containing figures, sidebars, footnotes or equations. Chunking cannot reliably fix reading order that was already wrong during extraction.

7. Charts and figures

Chart title and axis labels may be extracted as text, but that does not prove the trend or numerical values were understood. The cookbook recommends exporting the chart image, then using a VLM or human review to produce a factual description.

LangChain representation:

Python · chart description document 
from langchain_core.documents import Document

verified_chart_description = (
    "Quarterly revenue: Q1 = 10 million, "
    "Q2 = 12 million, Q3 = 15 million, Q4 = 18 million."
)

chart_doc = Document(
    page_content=verified_chart_description,
    metadata={
        "source": "data/report.pdf",
        "element_type": "chart_description",
        "image_path": "output/charts/chart_3.png",
    },
)

Validate: values, units, axis ranges, series names, legend labels and reporting period. Example numbers above are illustrative only.

Chapter 04 · Intermediate

Chunking strategies & metadata

Turn a large document into retrieval units without losing the meaning of each section.

What is chunking?

Chunking divides extracted document content into smaller pieces that can be embedded and retrieved. The objective is not merely to make text shorter; it is to create useful, context-preserving retrieval units.

Story: medical knowledge assistant

A hospital protocol is 70 pages. If the whole PDF is one chunk, a question about medication storage retrieves a huge, unfocused unit. If every sentence is isolated, the answer may lose the protocol heading and surrounding conditions. A useful chunk balances focused matching with enough context.

MARKDOWN + header splitter

Load the full Markdown, then split at `#`, `##`, `###`. Heading values become metadata, helping a retrieved paragraph retain its section context.

Section-aware

DOC_CHUNKS + HybridChunker

DoclingLoader's document chunk export uses document-aware chunking; your guide names HybridChunker as the default. It is a practical starting point for RAG.

Structure-aware

Compare the approaches

ApproachUseful whenWatch out for
Whole MarkdownInspecting conversion or custom processingDo not embed a huge document as one vector
MarkdownHeaderTextSplitterSections and heading context matterHeading recognition must be checked
DOC_CHUNKS / HybridChunkerWant document-aware chunkingInspect actual chunk boundaries and metadata

Metadata: the identity card for a chunk

Metadata carries provenance and context. Your source shows fields such as source file, page number and section. The cookbook also demonstrates explicit element type, table number and image path metadata.

Python · inspect metadata 
for index, doc in enumerate(chunks[:5], start=1):
    print("CHUNK:", index)
    print("CONTENT:", doc.page_content[:250])
    print("METADATA:", doc.metadata)
Production lesson: keep source/page identifiers so a retrieved chunk can be traced to the original document. Metadata keys can vary by package version; inspect your actual output.

Memory trick

“Structure → Split → Label → Verify”

Understand the document structure, split it into useful chunks, label each chunk with metadata, and verify the output against the source.

Chapter 05 · Intermediate

Embeddings & Qdrant vector database

Convert LangChain Documents into searchable vectors and retrieve relevant evidence.

What is an embedding?

An embedding model converts text into a numerical vector that represents semantic information. Similarity search compares a query vector with stored document vectors to find semantically related content.

Why do we need it?

Users rarely ask questions using exactly the same words as the source document. Vector representations can help retrieve conceptually related passages.

What is Qdrant?

Qdrant is the vector database used in your uploaded guide. It stores vectors together with associated payload/metadata and supports vector retrieval.

Keep the same embedding model/configuration consistent when creating document vectors and query vectors in a vector-search workflow.

Step 1 — install the packages

Terminal 
pip install langchain-huggingface

pip install qdrant-client

Step 2 — create embeddings

Python 
from langchain_huggingface import HuggingFaceEmbeddings

embeddings = HuggingFaceEmbeddings(
    model_name="sentence-transformers/all-MiniLM-L6-v2"
)

The model name is the example used in your source guide.

Step 3 — start Qdrant and create the vector store

Terminal · start local Qdrant 
docker run -p 6333:6333 qdrant/qdrant
Python · index LangChain Documents 
from langchain_qdrant import QdrantVectorStore
from qdrant_client import QdrantClient

client = QdrantClient(url="http://localhost:6333")

vectorstore = QdrantVectorStore.from_documents(
    docs,
    embeddings,
    url="http://localhost:6333",
    collection_name="docling_docs",
)

Inputs: `docs` is the list of LangChain Documents, `embeddings` is the embedding model, and `collection_name` identifies the Qdrant collection.

Step 4 — retrieve relevant documents

Python · retriever 
retriever = vectorstore.as_retriever(
    search_kwargs={"k": 5}
)

results = retriever.invoke(
    "What is quarterly revenue?"
)

for result in results:
    print(result.page_content)
    print(result.metadata)

`k=5` requests five results. Inspect both content and metadata to judge whether the retrieved evidence is useful.

Common troubleshooting

Qdrant connection refused
Confirm the Qdrant container is running and that the configured URL/port matches the local instance (`localhost:6333` in the source example).
Unexpected metadata keys
Print `doc.metadata` from your installed version. The source cookbook explicitly warns that metadata can differ across releases.
Weak retrieval results
Inspect extracted text, chunk boundaries, metadata and the actual top-k results. A vector database cannot repair missing or incorrectly extracted source content.
Chapter 06 · Intermediate to advanced

Retrieval fundamentals

Understand the retrieval stage and distinguish source-backed concepts from topics requiring additional study material.

What does a retriever do?

A retriever accepts a query and returns relevant documents from the indexed knowledge base. In your Qdrant example, the vector store is exposed as a LangChain retriever.

Python · basic retriever 
retriever = vectorstore.as_retriever(
    search_kwargs={"k": 5}
)

docs_found = retriever.invoke(
    "What is quarterly revenue?"
)

for doc in docs_found:
    print(doc.page_content)

Dense retrieval

Uses embedding vectors to retrieve semantically related content. The uploaded guide demonstrates embeddings and Qdrant vector retrieval.

Sparse

Sparse retrieval

Typically refers to term-based retrieval. Your uploaded files do not explain or implement sparse retrieval.

Hybrid retrieval

Typically combines multiple retrieval signals. The uploaded files do not provide a hybrid retriever implementation or configuration.

Retrieval quality checklist

  • Did the loader extract the correct source content?
  • Do chunks retain headings and table context?
  • Does metadata preserve source and page references?
  • Are the top-k retrieved passages relevant to the query?
  • Can you trace each retrieved passage back to its source?

Chapter 10 · Interview preparation

Interview questions & speaking practice

Use the reveal controls to practise explaining concepts without reading the answer first.

1–2 minute answer: explain your RAG ingestion pipeline

“For enterprise RAG, I first load complex documents through LangChain's `DoclingLoader`. It uses document understanding internally and returns LangChain Documents. I use Markdown export when I need to inspect the complete converted structure, or `DOC_CHUNKS` as a document-aware chunking starting point. I validate headings, tables, reading order and OCR output, and preserve metadata such as source and page. Then I generate embeddings and index the documents in Qdrant. At query time, I retrieve relevant chunks and can add reranking or contextual compression before sending context to the LLM. I also preserve source references so the answer can be traced back to the original document.”

Core interview questions

1. Why use DoclingLoader instead of a basic PDF loader?
Both can return LangChain Documents. DoclingLoader uses document understanding to better preserve structure such as headings, tables, layout and reading order, which can improve chunk quality and retrieval.
2. What is the difference between MARKDOWN and DOC_CHUNKS?
MARKDOWN returns the converted document as Markdown for inspection or custom splitting. DOC_CHUNKS returns multiple document-aware chunks and is the recommended starting point for RAG in your guide.
3. Why preserve metadata?
Metadata provides provenance and context such as source file, page and section. It helps trace retrieved evidence back to the original document.
4. How do you make tables searchable?
Use Markdown table output when sufficient, retaining headers and row relationships. The cookbook also demonstrates extracting tables to DataFrames and wrapping their text in LangChain Documents, but that low-level extraction uses Docling Core.
5. How do you process scanned PDFs?
A scanned page is an image, so OCR is needed to recognize text. The source configures an OCR-enabled Docling converter and passes it to DoclingLoader. Validate names, dates, decimal points, currency and table cells.
6. Why use Parent Document Retriever?
The system matches a small child chunk for precision, then returns the larger parent section to provide surrounding context. Your source describes the concept, not a full implementation.
7. What does contextual compression do?
It reduces retrieved material to important passages before the LLM uses it. Your guide lists fewer tokens, better relevance and lower cost as benefits.
8. Where does reranking fit?
After initial retrieval, before final context is passed to the LLM. Your source includes reranking in the production architecture but does not specify a model or code.
9. How do you prevent duplicate ingestion?
Convert a PDF once and reuse the conversion result, deduplicate content, and ensure OCR-derived content is indexed only once.
10. Why is a chart caption not automatically trustworthy?
A caption can misread values, units, axes or trends. Use a VLM or human review and validate against the original chart.

Scenario-based prompts

A finance PDF has a multi-page table. What do you validate?
Check column headers, row alignment, merged cells, page continuity, units and footnotes. Compare important financial values against the original pages. Preserve source/page provenance.
A research paper's retrieved answer mixes two columns. What do you investigate?
Inspect the original page and Docling conversion reading order. Do not assume chunking will repair a layout extraction problem.
Users ask about trends in charts but vector search cannot answer.
The chart may be represented as an image rather than meaningful text. Export the visual, create a verified description with a VLM or human review, and index that description as a LangChain Document with a source reference.

One-page revision

  • `DoclingLoader` returns LangChain Documents.
  • `MARKDOWN` is useful for inspecting the converted document.
  • `DOC_CHUNKS` is a useful RAG starting point.
  • `HybridChunker` is document-aware.
  • Metadata supports provenance and traceability.
  • Embeddings convert text into vectors.
  • Qdrant stores vectors and supports retrieval.
  • Parent retriever returns a larger parent after child matching.
  • Compression reduces retrieved content.
  • Reranking is a later retrieval refinement stage.
